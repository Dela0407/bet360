# bet360

bet360 is a React/Vite sportsbook interface with local SQLite development and a Netlify Functions + PostgreSQL deployment path. Wallet amounts, deposits, bets, and prizes are **demo credits only**; the app does not process payments or real-money wagers.

## Local development

Use Node.js 22.13 or newer and run:

```sh
npm install
npm run dev
```

This starts the Vite frontend and local Node API. The API uses SQLite at `data/bet360.sqlite` and listens on `127.0.0.1:3001`; Vite proxies `/api` requests to it. The database directory and SQLite files are ignored by Git. You can set `API_PORT` or `BET360_DB_PATH` before starting the server.

## Deploy to Netlify

1. Push the repository to GitHub and import it in Netlify. [Netlify's Vite setup](https://docs.netlify.com/build/frameworks/framework-setup-guides/vite/) is configured in `netlify.toml`: build command `npm run build`, publish directory `dist`, and functions directory `netlify/functions`.
2. Create/enable a Netlify Database for the site. Netlify makes its connection string available to Functions as `NETLIFY_DB_URL`. The function also accepts `DATABASE_URL` for a PostgreSQL provider outside Netlify.
3. Deploy. Netlify applies the SQL schema in `netlify/database/migrations` to the database as part of deployment. The account API function is routed to `/api/*`; no Vite proxy is used in production.
4. Optionally set `BET360_PASSWORD_PEPPER` in Netlify's runtime environment-variable settings (Functions scope). Keep it private and retain the same value; changing it prevents existing users' passwords from validating.

The production API uses PostgreSQL. It stores password hashes, hashed session tokens, account details, wallet ledger entries, and placed demo bets. Session cookies are HttpOnly and Secure on HTTPS. Database connection strings and password peppers must never be added to frontend `VITE_...` variables or committed to the repository.

The local development API remains SQLite-based; it does not automatically copy local SQLite accounts into Netlify Database. Deploy previews use Netlify's database branch behavior when available. To verify the deployed API, check `https://<your-site>/api/health` after deploying.

## Account and demo wallet

Demo-credit deposits simply add credits to an account. Sports bets debit the wallet; virtual game outcomes are generated by the API and any demo prize is credited to the wallet. No real payment methods or funds are involved. The current interface and backend are not a production gambling or payment service.

## Checks

```sh
npm run lint
npm run build
npm run test:api
npm run test:netlify
```

The SQLite API test uses and removes a temporary database. The Netlify API unit tests check request validation and credit conversion.
